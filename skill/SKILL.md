# 입고살까

가격 판단과 개인 적합성을 분리하고, 사용자가 둘을 판단한 뒤 실행 승인을 받는다. 구매·보류·안 사기를 동등하게 둔다. [도구 계약](references/tools.md)을 먼저 읽는다.

## 표시 순서

한 응답은 **결론 → 상품/착장 이미지 → 스타일·소재·실루엣·가격 각 한 줄 → 다음 선택 2~3개** 순서다. JSON 전체나 미확인 항목 배열을 그대로 읽어 주지 않는다. `summary`, `styleOpinion`, `alternativeDifference`를 우선 사용한다. 이미지 경로는 호스트의 이미지 표시 도구로 실제 열어 보여 준다.

호스트의 대화 ID를 `FASHION_SESSION` 또는 `--session`으로 매 호출 전달한다. `sessionLimits`는 같은 대화에서 최초 성공 호출에만 나온다. 이 공통 안내는 뒤에 한 번만 보여 주고 이후 카드에서는 반복하지 않는다. 새 대화에는 새 ID를 쓴다. `notice`, `unknowns`, `uncertainties`는 상세 요청 때만 보여 준다. 동의 필요·이전 견적 폐기처럼 **지금 행동을 막는 상태**는 즉시 짧게 알린다.

모의 결제는 의도한 데모 동작이다. 미구현 문제나 장애로 보고하지 않는다.

## 실제 실행 연결

저장소 루트는 이 파일의 `..`이다. `bun src/cli.ts <command>`를 저장소 루트에서 실행한다. `FASHION_HOME`은 사용자가 제공한 기존 비공개 데이터 폴더, `OBA_KEY_FILE`은 기존 A.X 키 파일이다. 사진·프로필을 스킬 폴더로 복사하지 않는다.

- 가격 우선: `search_catalog --budget 80000 --item 맨투맨`.
- 특정 상품: ID가 있으면 `--source ff|own --sku SKU`의 `fit_card`부터 시작. 이름만 있으면 `search_catalog --budget <사용자 예산> --item "MLB 바람막이"`처럼 브랜드와 종류를 함께 검색한다. 예산이 없으면 한 번만 묻는다. 전체 재추천은 요청받을 때만.
- 가격 근거: `price_card --source ... --sku ...`.
- 적합성: `fit_card --source ... --sku ...`.
- A.X: `explain --request "<개인정보 없는 일반 요청>"`.
- 착장: `tryon --source own --sku OWN-001`.
- 모의 견적: `quote`. 다음 사용자 응답을 받은 뒤 `approve_and_pay`.

F&F 명령 출력과 원본 사진은 **로컬 사용자 화면에만 표시**한다. 원격 모델 도구의 stdout이나 대화에 자동으로 붙이지 않는다. 외부 모델에는 일반 요청만 보내며 F&F 상품 행·이미지·가격·프로필 수치를 보내지 않는다.

## 가격 카드

F&F 가격은 정적 샘플 참고가격이며 실제 판매가·정가·할인·최저가가 아니다. 배송비·세금·쿠폰을 모르므로 총액은 미확정이다. 최대 3개 후보와 최대 2개 동종 대안을 비교하고, 예산 차이는 참고가격 기준이라고 표시한다. 아동 상품을 성인에게 추천하지 않는다.

“가격 납득 / 대안 보기 / 판단 보류?”를 묻고 기다린다. 이미 발화에 가격 수용이 있으면 다시 묻지 않는다. 정상 빈 결과는 `summary` 한 줄과 `nextSteps`의 2~3개 선택지로 끝낸다. `not_in_catalog`는 **현재 카탈로그에 없음**, `over_budget`는 **현재 예산 초과**다. `alternatives`는 원래 요청 상품이 아니라 가까운 대안이라고 표시한다. 예산을 자동으로 올리지 않는다.

## 적합성과 착장

[스타일 사전](references/style-knowledge.md)과 [소재 사전](references/fabric-knowledge.md)을 사용한다. 의견은 적용한 규칙 ID를 끝에 붙인 **한 줄**로, 사이즈 판단은 별도 `sizing`으로 둔다. 원본 프로필의 미제공 값이나 치수를 추정하지 않는다. 상품 실측표가 없으면 사이즈는 `핏 미확인`이다.

핏 선호는 기존 `fitPreference`, 체형·장르·색 대비·착용 상황은 로컬 `profile/style-preferences.json`을 읽는다. 후자는 사용자가 말한 값만 기록하고 개인 수치나 사진을 저장소 문서에 복사하지 않는다. 사진 기반 버전과 판단 버전은 분리하여 선호를 바꿔도 기존 착장을 재생성하지 않는다.

착장 성공 시 호스트가 **실제 이미지를 열어** 어깨·가슴 여유, 상하의 볼륨, 기장, 소매, 명암 대비를 관찰한다. `demo/<SKU>.style.json` 또는 `fit_card --observation <로컬 파일>`에 상품 ID·프로필 버전·이미지 경로·SHA-256과 구조화된 관찰을 기록한다. 현재 이미지가 아닌 관찰은 도구가 거절한다. A.X는 관찰자로 쓰지 않는다. 이미지가 없으면 `상품 기준` 의견으로 진행하며 본 것처럼 쓰지 않는다.

소재는 상품 명세가 우선이다. 명세가 없고 사진을 직접 확인했다면 보이는 드레이프·표면·기장만 `이미지 추정`으로 표시한다. 사진만으로 혼용률·gsm·oz·게이지·통기성·수축률을 확정하지 않는다. 소재, 소재 가치, 실루엣·착용감은 각각 한 줄이다.

현재 F&F 이미지는 로컬 표시 전용이다. `tryon --source ff`는 외부 전송하지 않는다. `own`은 저장소에서 직접 만든 가상 의류 디자인이며 F&F 상품과 무관하다. 자체 디자인 착장을 F&F 상품의 결과에 붙이지 않는다.

OpenAI 외부 처리에는 별도 동의 파일과 `claw` 서비스 계정 키 참조가 필요하다. 승인 슬롯은 `body_front`와 `face_45`뿐이며 승인된 생성 횟수를 넘지 않는다. 키가 없으면 `키 대기`, 이미지 0장이다. 생성된 척하는 정적 대체 이미지를 표시하지 않는다.

성공한 경우 실제 결과를 열어 얼굴·체형·의류가 유지되는지 확인한다. 캐시는 캐시라고 표시하고 상품 ID·프로필 버전이 다른 결과는 재사용하지 않는다. “선호 / 다른 옵션 / 사이즈 확인 / 보류?”의 사용자 응답을 기다린다.

## 승인과 결과

두 판단에 대한 사용자 응답이 있어야 `quote`에 `--price accepted --fit accepted-with-unknown-size --option "<사용자가 확인한 옵션>"`을 전달한다. 사이즈 미확인을 받아들였다는 판단도 모델이 대신 작성하지 않는다.

현재 구현은 **simulation 전용**이다. 견적에는 상품·옵션·수량·프로필 버전·참고가격·유효 시간이 묶이며 수취인·체인 없음, 전송액·수수료 0이다. 실제 주문·배송은 없다.

출력된 견적과 정확한 `approval` 문자열을 보여 주고 **다음 사용자 응답에서 명시 승인**을 받는다. `approve_and_pay --quote <ID> --approval "<그 응답>"`을 한 번 호출한다. 애매한 긍정·가격 수용·사진 동의를 승인으로 바꾸지 않는다. 보류는 호출하지 않고, 취소는 `--cancel`이다.

승인은 `승인 1234`처럼 짧고 현재 견적에만 결합된다. 코드는 되풀이하지 않는다. 사용자가 상품·옵션을 바꾸면 즉시 `change_selection`을 호출해 이전 미실행 견적을 폐기한다. 새 `quote`도 이전 미실행 견적을 자동 폐기한다. 가격·핏을 다시 판단한 뒤 새 견적과 새 승인을 받는다. 이전 견적 응답은 `superseded`, 짧은 안내 한 줄이다.

실행 전 취소는 `취소됨(모의)`, 실행 후 취소 요청은 `실행 후 취소 불가`다. 이미 실행한 영수증을 취소 성공으로 읽지 않는다. 재승인은 기존 영수증을 재사용하고 취소한 견적은 다시 실행되지 않는다. 결과는 `simulated` 또는 `cancelled`이며 실제 송금은 항상 0회다.

## 시연과 보관

`bun src/demo.ts`는 scripted-demo 판단과 승인으로 두 경로를 리허설하고 개인 데이터 폴더의 `demo/`에 결과를 쓴다. 이것은 소유자의 실제 승인 기록이 아니다.

기본 가격 우선 질의는 “8만원 이하 맨투맨”, “5만원 이하”는 빈 결과 경계 조건이다. 특정 상품은 자체 디자인 `OWN-001`로 F&F와 분리한다.

F&F 원본·다운로드 사본·로컬 카드·파생 결과는 행사 종료 후 삭제 대상이다. 원본 인물 사진은 보존하며 이 정리와 섞지 않는다. 사진·키·프로필·F&F 자료·생성 결과는 Git에 넣지 않는다.
