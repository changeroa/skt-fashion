# 입고살까

가격 판단과 개인 적합성을 분리하고, 사용자가 둘을 판단한 뒤 실행 승인을 받는다. 구매·보류·안 사기를 동등하게 둔다. [도구 계약](references/tools.md)을 먼저 읽는다.

## 실제 실행 연결

저장소 루트는 이 파일의 `..`이다. `bun src/cli.ts <command>`를 저장소 루트에서 실행한다. `FASHION_HOME`은 사용자가 제공한 기존 비공개 데이터 폴더, `OBA_KEY_FILE`은 기존 A.X 키 파일이다. 사진·프로필을 스킬 폴더로 복사하지 않는다.

- 가격 우선: `search_catalog --budget 80000 --item 맨투맨`.
- 특정 상품: 사용자가 지정한 `--source ff|own --sku SKU`의 `fit_card`부터 시작. 전체 재추천은 요청받을 때만.
- 가격 근거: `price_card --source ... --sku ...`.
- 적합성: `fit_card --source ... --sku ...`.
- A.X: `explain --request "<개인정보 없는 일반 요청>"`.
- 착장: `tryon --source own --sku OWN-001`.
- 모의 견적: `quote`. 다음 사용자 응답을 받은 뒤 `approve_and_pay`.

F&F 명령 출력과 원본 사진은 **로컬 사용자 화면에만 표시**한다. 원격 모델 도구의 stdout이나 대화에 자동으로 붙이지 않는다. 외부 모델에는 일반 요청만 보내며 F&F 상품 행·이미지·가격·프로필 수치를 보내지 않는다.

## 가격 카드

F&F 가격은 정적 샘플 참고가격이며 실제 판매가·정가·할인·최저가가 아니다. 배송비·세금·쿠폰을 모르므로 총액은 미확정이다. 최대 3개 후보와 최대 2개 동종 대안을 비교하고, 예산 차이는 참고가격 기준이라고 표시한다. 아동 상품을 성인에게 추천하지 않는다.

“가격 납득 / 대안 보기 / 판단 보류?”를 묻고 기다린다. 정상 빈 결과는 조건 변경 또는 종료로 안내한다.

## 적합성과 착장

원본 프로필의 미제공 값을 추정하지 않는다. 상품 실측표가 없으므로 `핏 미확인`이며, 과거 취향 기록이 없으면 `과거 선호 없음`이다. A.X는 이미지를 보지 않았다.

현재 F&F 이미지는 로컬 표시 전용이다. `tryon --source ff`는 외부 전송하지 않는다. `own`은 저장소에서 직접 만든 가상 의류 디자인이며 F&F 상품과 무관하다. 자체 디자인 착장을 F&F 상품의 결과에 붙이지 않는다.

OpenAI 외부 처리에는 별도 동의 파일과 `claw` 서비스 계정 키 참조가 필요하다. 승인 슬롯은 `body_front`와 `face_45`뿐이며 승인된 생성 횟수를 넘지 않는다. 키가 없으면 `키 대기`, 이미지 0장이다. 생성된 척하는 정적 대체 이미지를 표시하지 않는다.

성공한 경우 실제 결과를 열어 얼굴·체형·의류가 유지되는지 확인한다. 캐시는 캐시라고 표시하고 상품 ID·프로필 버전이 다른 결과는 재사용하지 않는다. “선호 / 다른 옵션 / 사이즈 확인 / 보류?”의 사용자 응답을 기다린다.

## 승인과 결과

두 판단에 대한 사용자 응답이 있어야 `quote`에 `--price accepted --fit accepted-with-unknown-size --option "<사용자가 확인한 옵션>"`을 전달한다. 사이즈 미확인을 받아들였다는 판단도 모델이 대신 작성하지 않는다.

현재 구현은 **simulation 전용**이다. 견적에는 상품·옵션·수량·프로필 버전·참고가격·유효 시간이 묶이며 수취인·체인 없음, 전송액·수수료 0이다. 실제 주문·배송은 없다.

출력된 견적과 정확한 `approval` 문자열을 보여 주고 **다음 사용자 응답에서 명시 승인**을 받는다. `approve_and_pay --quote <ID> --approval "<그 응답>"`을 한 번 호출한다. 애매한 긍정·가격 수용·사진 동의를 승인으로 바꾸지 않는다. 보류는 호출하지 않고, 취소는 `--cancel`이다.

변경·만료된 견적은 새 승인을 받는다. 결과는 `simulated` 또는 `cancelled`이며 실제 송금은 항상 0회다. Maroo·Agentic Pay 성공이나 실제 의류 구매라고 하지 않는다.

## 시연과 보관

`bun src/demo.ts`는 scripted-demo 판단과 승인으로 두 경로를 리허설하고 개인 데이터 폴더의 `demo/`에 결과를 쓴다. 이것은 소유자의 실제 승인 기록이 아니다.

기본 가격 우선 질의는 “8만원 이하 맨투맨”, “5만원 이하”는 빈 결과 경계 조건이다. 특정 상품은 자체 디자인 `OWN-001`로 F&F와 분리한다.

F&F 원본·다운로드 사본·로컬 카드·파생 결과는 행사 종료 후 삭제 대상이다. 원본 인물 사진은 보존하며 이 정리와 섞지 않는다. 사진·키·프로필·F&F 자료·생성 결과는 Git에 넣지 않는다.
